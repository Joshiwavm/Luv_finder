# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Blind spectral-line finding in the UV plane for ALMA data: a UV-domain Gaussian line
model is grid-searched against visibilities with a matched filter; a jackknifed copy of
the data gives the noise reference. Real data (SPT-CL J0459-4947, Band 1 and the
Band 3 mosaic) export and search per pointing; see ROADMAP.md for what is still open.

## Environment and commands

- `conda activate luv` (arm64 Python 3.12, native; no Rosetta). Install: `pip install -e ".[casa,dev]"`.
- Linux (Allegro): `luv` lives at `/almastorage/allegro6/marrewijk/miniconda3/envs/luv`; activate by full path from bash, as in the parent `ALMA_analysis/CLAUDE.md`. casatools/casatasks are pinned to 6.7.5.18 in `pyproject.toml`: the 6.7.6.14 wheel ships no libcrypto and `import casatasks` fails. Do not work around it with `LD_PRELOAD`; it breaks Python's `ssl`.
- Run everything from the repo root; configs and outputs use root-relative paths.
- `pytest` — CASA-free, uses `tests/fixtures/line13_line9_small.npz`. `pytest -m casa` simulates the smoke preset (needs CASA). `pytest --plots` also writes figures and a contact sheet to `plots/`.
- `pre-commit run --all-files` — ruff lint + format, nbstripout. Keep it clean.
- `make -C docs html` — Sphinx (furo, nbsphinx); tutorials in `docs/source/tutorials/` are committed executed and never re-run by the build.
- CLIs: `luv-run <run.yaml> search [--workers N]|fit|summary|plots` (see `run.py`), `luv-mock <yaml>`, `luv-export --ms X --out X.npz`, `luv-find --ms X[.npz] [--grid yaml] [--jackknife] [--field N] [--continuum-order N|none] [--catalogue out.ecsv [--fit]]` (several fields and no `--field`: all searched, PB-corrected and combined).

## Architecture

- `luv_finder/data.py` — `DataHandler` holds one frozen `Chunk` per (field, spw): `X = w * V` and the weight of every visibility `w` (float32, 0 where flagged; `flag` is `w == 0`) as `(n_chan, n_row)`, `u`/`v`/`time`/`baseline`/`scan` (`OBSERVATION_ID << 32 | SCAN_NUMBER`) per row, `freq` per channel. Stokes I from `WEIGHT_SPECTRUM` (or `WEIGHT`) and `FLAG`; autocorrelations and flagged rows dropped on reading. `iter_chunks` reads one spw over all fields and corrects its weights (`reweighted`): `weight_scale` measures the noise over the weights per (scan, channel) from disjoint pairs of each baseline's integrations at most `MAX_GAP` = 450 s apart in any field (a mosaic's next visit; a pair spanning two scans counts in both), `sum w z^2 / 2 sum w` with a robust median check, and the weights are divided by it, so atmospheric lines and changing weather are in the weights before anything else. Never hard-code a correction. Positions are arcsec east/north of `Metadata.ref`, and each chunk's `offset` is its field centre in that frame, so one grid serves every pointing. `Metadata` is dataset-level. NPZ is written streaming, one chunk at a time; `from_npz(fields=...)` loads only those fields. `load(path, fields)` opens an NPZ or an MS; `fields_in(path)` lists the target fields without loading visibilities. `jackknife()` pairs each baseline's own integrations in the field in time order (first with second, ...; `_pairs`), so a mosaic field seen once per visit, months apart (ASPECS 1.2 mm), still pairs most rows; pair weights per visibility. `channel_noise(chunks)` / `DataHandler.channel_noise()` measure the channels on the jackknife per spw, a `ChannelNoise(scale, rho)`: `scale` the noise power over the weights per channel (a check: ~1 once reweighted), `rho` the correlation `(1, rho_1, ...)` up to the first lag consistent with zero (Hanning: 2/3, 1/6; independent: `(1,)`). A noiseless jackknife raises; noiseless mocks pass `None` or the noisy data's. CASA is reached lazily through `_casa.py`, so the NPZ path works without it. Frequencies stay in the MS's frame; `Metadata.from_ms` warns unless it is LSRK (`check_frame`), since TOPO differs by up to ~30 km/s.
- `luv_finder/model.py` — `Model` + `Gaussian` (2D spatial x 1D spectral, evaluated analytically in UV). Parameters are exposed as `src_{NN}_{attr}`; the matched filter routes values back via `key.split("_", 2)[-1]`. `covariance(bmaj, bmin, pa)` gives a shape's sky covariance and `envelope(uw, vw, cov, xp=)` its visibility amplitude: the one formula the filter, the fit and the model use.
- `luv_finder/kernel.py` — the spatial collapse, in JAX: `_collapse` scans a window's channels with the position phases as a separable complex GEMM advanced by recurrence, weighting each visibility by the trial source's own amplitude (a point: noise weights only); `dra` blocks (`utils.BLOCK_BYTES`) bound memory. `point_moments` collects, at one position, the per-channel moments the fit needs. `limit_cores`/`default_cores` pin the process to a quarter of the cores, at most all but two, because the machines are shared.
- `luv_finder/matchedfilter.py` — `MatchedFilter` (float64 via a scoped `jax.enable_x64`): `Model.grid` axes (scalar = fixed, array = enumerate; rows are their product in `GRID_KEYS` order), one field at a time. The trial line centres are one lattice, `MatchedFilter.freqs` (the finest channel width from the lowest channel, through every window; a single window's centres are its channels). `_spectral` fits the line template at every centre inside a window with per-lag normalisation (no FFT, no padding), jointly per position with a polynomial continuum (`continuum_order`, default `model.CONTINUUM_ORDER` = 1, which the fit shares and `Run.fit` takes from the run's `filter`), refitted at each position without the channels of its other lines (`_masked`: a line peaking at `MASK_SNR` = 5 masks `MASK_FWHM` = 1 template FWHM; each template keeps its own, so an isolated line gets the joint fit and a bright neighbour no longer bends the continuum of a faint one; errors are per position; only `dra` rows holding such a line are refitted, by `lax.cond` per row, elsewhere the joint fit stands; the refit runs twice, the second from the first's peaks, and a peak within `MASK_FWHM` of a centre is that centre's own line and masks nothing there), normalised by the exact variance `h^T C h` under `rho` (`channel_noise="measure"` on the jackknife, default; None = `(1,)`; or `{spw: ChannelNoise}`). Windows join (`window_groups`, and so `run.window_units`) where they overlap or their gap is narrower than the widest template; each evaluates centres up to one widest FWHM beyond its edges within its group (`_reach`), and they add by inverse variance at their shared centres in `_search`, the joint fit of one template with a continuum per window, the PB^2/sigma^2 algebra along frequency; each window's own weights and `rho` (spws can differ in correlator setup) are in its error first. `run()` fills `mf.result`, a `SearchResult` (S/N, peak flux density and error per position x template x channel, coverage, jackknife), which `catalogue.py` consumes. `pb_corrected` divides one pointing's result by its primary beam (masked below `pb_limit`), `combine_pointings` merges pointings by inverse variance (PB^2/sigma^2) on their shared lattice; `build_grid` makes the search axes from YAML (position lattice anchored at the reference, out to `pb_limit`, default 0.2) and `search_pointings(path, ...)` runs every field of an NPZ/MS through the filter, so overlapping pointings are always PB-corrected and combined before cataloguing (a single pointing is PB-corrected too). `combine_pointings` adds the pointings one at a time into running sums (`sum w`, `sum w flux`, `sum coverage^2`) on a lattice that grows only where a pointing reaches beyond it, so `search_pointings` holds the mosaic plus one pointing. The response is in S/N units (unit variance under the null); `total_flux` cancels in the kernel normalisation and is rejected as a grid key. Mock `snr` is the optimal S/N.
- `luv_finder/imaging.py` — natural-weighted dirty cubes on a regular grid by jax-finufft type-1 NUFFT (`dirty_cube`, `pointing_cubes`), moment-8/continuum maps (`dirty_maps`) and their linear mosaic (`mosaic_dirty_maps`), at res/4 pixels: `pointing_cubes` oversamples the search grid twice (`oversample`). Diagnostics only; the search does not use them.
- `luv_finder/catalogue.py` — from a `SearchResult` to line candidates, all against the one jackknife. S/N is the filter's, already corrected for correlated channel noise, so `jackknife_spread` should read ~1 (1.4-1.6 means a search with `channel_noise=None` on Hanning data). `response_correlation` measures the null correlation rho (= expected response shape; half-power ellipsoid sets grouping); `groups` merges 3x3x3 local maxima of the best-template S/N inside a brighter one's ellipsoid; `catalogue` adds the cumulative likelihood ratio N_data/N_jk (van Marrewijk+25, >= k=3; above the jackknife max a lower limit, the last finite value) and the fidelity 1 - N_jk/N_data per S/N bin, N_jk from a Gaussian tail fitted to the jackknife groups (ASPECS, >= 0.6); `detected` if both pass (`rule="and"`, `catalogue.DETECTION_RULE`, default) or either (`"or"`), as an astropy table (`cat[cat["detected"]]`). A group at S/N >= `BRIGHT_SNR` = 100 is flagged (`bright_lines`: a warning, a line in `Run.summary`), since its sidelobes reach a few sigma; nothing is subtracted. `merge_catalogues(cats)` joins the catalogues of several searches of one dataset (e.g. one per spw, when the whole band does not fit in memory) and recomputes the likelihood ratio, fidelity and `detected` on their pooled groups; each search's own meta goes to `meta["parts"]`. Data negatives: diagnostic only. Needs a uniform position lattice.
- `luv_finder/fit.py` — `fit_lines(data_or_path, cat)` refines each detected line by least squares in the visibilities: a Gaussian source (position and sky covariance `(s_ee, s_nn, s_en)`, so a point is zero size) whose spectrum is a Gaussian line on a polynomial continuum, times each pointing's PB at the source, in every window within one FWHM of the line (its own continuum per window) of every pointing with PB >= 0.2, without the channels of the catalogue's other lines at S/N >= `MASK_SNR` within a resolution element (`_without`). Exact reduction: chi^2 depends on the data only through `S = sum_p PB_p sig_p` and `Q = sum_p PB_p^2 W_p`; every derivative in position and shape is the model times a polynomial in (u, v), so one pass (`kernel.point_moments`, per-channel moments) gives chi^2, gradient and Gauss-Newton matrix exactly. The spectrum is fitted on the moments without another pass (trust-exact), and `scipy.optimize.minimize` (L-BFGS-B) moves position and shape, as two axis variances bounded at zero and an angle, on the profiled chi^2 from the matched filter's peak (4-16 passes a line); an axis on its bound gets a NaN error. The line width is bounded at `MIN_WIDTH` = 70 km/s (no channel response in the model), refitted there with a NaN error. `meta["spectra"]` keeps each line's spectrum and best fit; `imaging.line_maps` gives moment-0 maps. Errors `2 (J^T W J)^-1`, corrected for the channel correlation by a sandwich estimator (`_correlation_scale`). `imaging.line_maps` uses the line's `home_window` only. A failing line only warns. `luv-find --catalogue X --fit` writes the `fit_*` columns into the ECSV.
- `luv_finder/mock.py` — `MockObservation`: cube -> `simobserve` -> `tclean` -> `output/ms_files/<name>/`; `pointings` (a mosaic) and `windows` (one `simobserve` per window, `concat`enated, the same channel width in Hz). YAML presets in `configs/mocks/` (`mosaic`, `tunings`, `edge` for pointings and windows).
- `luv_finder/_casa.py` — the only place that imports `casatools`/`casatasks`. It presets `casaconfig.config.logfile` so CASA writes to `logs/` (override with `LUV_CASA_LOG_DIR`) instead of scattering `casa-<timestamp>.log` in the working directory. Never import CASA directly; use `tools()`/`tasks()`, or call `configure_logging()` first if you must.
- `luv_finder/utils.py` — constants `C`/`ARCSEC` and the analytic ALMA primary beam: an Airy pattern scaled to FWHM = 1.13 lambda/D (Technical Handbook, the real beam); simobserve's CASA beam is ~1.165, hence `tests/test_primary_beam.py` compares mocks with the default beam at 6%. Also the mock weight helper.
- `luv_finder/plotting.py` — all diagnostic figures. Each returns its `Figure` (built without pyplot) and writes `<plots_dir>/<name>.png` only when `plots_dir` is given; each is drawn inside `plotting.style()`, the package style `luv.mplstyle` (serif, inward ticks), so callers' rcParams are untouched. `weights_check` draws Re V per channel against the spread the weights predict (as read, reweighted, pooled over fields, with the counting band); `reliability_check` shows the fidelity against the negated data next to the jackknife's; `peak_snr_map` and `filter_responses` draw from saved run products. `MatchedFilter.plot_response` is a thin wrapper; the CLI sets the Agg backend itself.
- `luv_finder/run.py` — `Run`, the user-facing front door: a YAML (`data`, `output`, optional `grid`, `units`, `filter`, `reliability`, `near_miss`, `cores`) in, every product in `output/`: `export/<unit>.npz`, `units/<unit>.ecsv` (+ `unit`, `unit_id`), `units/<unit>_maps.npz` (peak S/N per position, the filter response of every group, data and jackknife), `units/<unit>_weights.npz` (weight scales per (scan, channel), channel noise), `catalogue.ecsv`, `lines_fit.ecsv`, `line_maps.npz`. A unit is the spectral windows that overlap in frequency (`window_units`). `search(workers=n)` shares the units by claim files (several processes or machines), skipping what is on disk; `merge`, `fit` (detections + near misses, duplicates across units), `summary`, `diagnostics` (the weights figure per unit). `run.plot.*` and `Run.open(output)` read saved products only, so no figure repeats a search. `luv-run <yaml|output> search|merge|fit|summary|diagnostics|plots|release`.
- `luv_finder/cli/` — argparse wrappers only; no science logic.
- `configs/mocks/` and `configs/grids/` pair by filename; the `size_*` mocks take their source from the grid (`--grid`); `configs/README.md` covers the pairing. Antenna configs are not vendored: presets name files CASA ships (`alma.cycle13.3.cfg`), resolved by `mock.resolve_antenna_config`. `data/ output/ support/ plots/ logs/` are gitignored products.
- Test configs live in `configs/`, not under `tests/`: `tests/test_mock.py` loads `configs/mocks/smoke.yaml` and `configs/grids/smoke.yaml` rather than hardcoding parameters, so presets and tests cannot drift apart.

## Conventions

- DRY and KISS: one implementation per concept, thin wrappers, no speculative abstractions. `Run` is the one user-facing layer over the library; science logic stays in the modules it calls.
- Data I/O, the model and the mocks are numpy/scipy; the collapse (`kernel.py`), the filter, the imaging and the fit's derivatives are JAX. `model.envelope(..., xp=)` and `utils.primary_beam(..., xp=)` are the one formula each for both.
- No nested sampling or other samplers until ROADMAP.md says otherwise: detection is a grid search, and catalogued lines are refined by a deterministic least-squares fit (`fit.py`).
- No notebooks outside `docs/source/tutorials/` in the repo; the hands-on notebooks live in `ALMA_analysis/Notebooks/luv_finder/`, outside it. New workflows become `Run` steps or CLI commands + tests.
- Real-data organisation/concatenation belongs to `alma-data-prep`, not here.
- Planned work and open problems (JAX, catalog, primary beam + mosaics): see ROADMAP.md.
- Notion holds the paper drafts: the Luv-finder page is the method chapter of the A&A methods paper (explanation, math and code excerpts interleaved), and its subpage is the JOSS paper, laid out like JOSS's example paper. Use the terminology of Vio & Andreani (2021, arXiv:2107.09378): H0/H1, template s, statistic T(x), SNR, P_FA, threshold gamma. Concise and accurate; state each thing once. Publication plan: ROADMAP.md section 4.
- When a PR into main merges, run the `notion-sync` skill (`.claude/skills/notion-sync/`) to bring both Notion pages up to date.
