# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Blind spectral-line finding in the UV plane for ALMA data: a UV-domain Gaussian line
model is grid-searched against visibilities with a matched filter; a jackknifed copy of
the data gives the noise reference. Real data (SPT-CL J0459-4947, Band 1 and the
Band 3 mosaic) export and search per pointing; see ROADMAP.md for what is still open.

## Environment and commands

- `conda activate luv` (arm64 Python 3.12, native; no Rosetta). Install: `pip install -e ".[casa,dev]"`.
- Linux (Allegro): `luv` lives at `/almastorage/allegro6/marrewijk/miniconda3/envs/luv`; activate by full path from bash, as in the parent `ALMA_analysis/CLAUDE.md`. casatools/casatasks are pinned to 6.7.5.18 in `pyproject.toml`: the 6.7.6.14 wheel ships no libcrypto and `import casatasks` fails. Do not work around it with `LD_PRELOAD`; it breaks Python's `ssl`.
- Run everything from the repo root; configs and outputs use root-relative paths.
- `pytest` — CASA-free, uses `tests/fixtures/line13_line9_small.npz`. `pytest -m casa` simulates the smoke preset (needs CASA). `pytest --plots` also writes figures and a contact sheet to `plots/`.
- `pre-commit run --all-files` — ruff lint + format, nbstripout. Keep it clean.
- `make -C docs html` — Sphinx (furo, nbsphinx); tutorials in `docs/source/tutorials/` are committed executed and never re-run by the build.
- CLIs: `luv-mock <yaml>`, `luv-export --ms X --out X.npz`, `luv-find --ms X[.npz] [--grid yaml] [--jackknife] [--field N] [--continuum-order N|none] [--catalogue out.ecsv [--fit]]` (several fields and no `--field`: all searched, PB-corrected and combined).

## Architecture

- `luv_finder/data.py` — `DataHandler` holds one frozen `Chunk` per (field, spw): `X = w * V` and `flag` as `(n_chan, n_row)`, `u`/`v`/`time`/`baseline`/`w_row` per row, `freq` per channel. Stokes I from `WEIGHT` and `FLAG`; autocorrelations and flagged rows dropped on reading. Positions are arcsec east/north of `Metadata.ref`, and each chunk's `offset` is its field centre in that frame, so one grid serves every pointing. `Metadata` is dataset-level. NPZ is written streaming, one chunk at a time; `from_npz(fields=...)` loads only those fields. `load(path, fields)` opens an NPZ or an MS; `fields_in(path)` lists the target fields without loading visibilities. `jackknife()` pairs integrations by baseline. `channel_correlation(chunks)` / `DataHandler.channel_correlation()` measure the noise correlation between channels on the jackknife per spw, `(1, rho_1, ...)` up to the first lag consistent with zero (Hanning: 2/3, 1/6; independent: `(1,)`); a noiseless jackknife reads signal residuals as correlation, so mocks pass the noisy data's. CASA is reached lazily through `_casa.py`, so the NPZ path works without it.
- `luv_finder/model.py` — `Model` + `Gaussian` (2D spatial x 1D spectral, evaluated analytically in UV). Parameters are exposed as `src_{NN}_{attr}`; the matched filter routes values back via `key.split("_", 2)[-1]`. `covariance(bmaj, bmin, pa)` gives a shape's sky covariance and `envelope(uw, vw, cov, xp=)` its visibility amplitude: the one formula the filter, the fit and the model use.
- `luv_finder/kernel.py` — the spatial collapse, in JAX: `_collapse` scans a window's channels with the position phases as a separable complex GEMM advanced by recurrence, weighting each visibility by the trial source's own amplitude (a point: noise weights only); `dra` blocks (`utils.BLOCK_BYTES`) bound memory. `point_moments` collects, at one position, the per-channel moments the fit needs. `limit_cores`/`default_cores` pin the process to a quarter of the cores, at most all but two, because the machines are shared.
- `luv_finder/matchedfilter.py` — `MatchedFilter` (float64 via a scoped `jax.enable_x64`): `Model.grid` axes (scalar = fixed, array = enumerate; rows are their product in `GRID_KEYS` order), one field at a time. `_spectral` applies the line template centred on every channel with per-lag normalisation (no FFT, no padding), fitted jointly per position with a polynomial continuum (`continuum_order`, default 2), normalised by the exact variance `h^T C h` under the channel correlation (`channel_correlation="measure"` on the jackknife, default; None = `(1,)`; or `{spw: rho}`). `run()` fills `mf.result`, a `SearchResult` (S/N, peak flux density and error per position x template x channel, coverage, jackknife), which `catalogue.py` consumes. `pb_corrected` divides one pointing's result by its primary beam (masked below `pb_limit`), `combine_pointings` merges pointings by inverse variance (PB^2/sigma^2) on their shared lattice; `build_grid` makes the search axes from YAML (position lattice anchored at the reference, out to `pb_limit`, default 0.2) and `search_pointings(path, ...)` runs every field of an NPZ/MS through the filter, so overlapping pointings are always PB-corrected and combined before cataloguing (a single pointing is PB-corrected too). The response is in S/N units (unit variance under the null); `total_flux` cancels in the kernel normalisation and is rejected as a grid key. Mock `snr` is the optimal S/N.
- `luv_finder/imaging.py` — natural-weighted dirty cubes on a regular grid by jax-finufft type-1 NUFFT (`dirty_cube`, `pointing_cubes`), moment-8/continuum maps (`dirty_maps`) and their linear mosaic (`mosaic_dirty_maps`). Diagnostics only; the search does not use them.
- `luv_finder/catalogue.py` — from a `SearchResult` to line candidates, all against the one jackknife. S/N is the filter's, already corrected for correlated channel noise, so `jackknife_spread` should read ~1 (1.4-1.6 means a search with `channel_correlation=None` on Hanning data). `response_correlation` measures the null correlation rho (= expected response shape; half-power ellipsoid sets grouping); `groups` merges 3x3x3 local maxima of the best-template S/N inside a brighter one's ellipsoid; `catalogue` adds the cumulative likelihood ratio N_data/N_jk (van Marrewijk+25, >= k=3, lower limit above the jackknife max) and the erf-fitted fidelity 1 - N_jk/N_data (ASPECS, >= 0.6), as an astropy table (`cat[cat["detected"]]`). Data negatives: diagnostic only. Needs a uniform position lattice.
- `luv_finder/fit.py` — `fit_lines(data_or_path, cat)` refines each detected line by least squares in the visibilities: a Gaussian source (position and sky covariance `(s_ee, s_nn, s_en)`, so a point is zero size) whose spectrum is a Gaussian line on a polynomial continuum, times each pointing's PB at the source, in the line's window of every pointing with PB >= 0.2. Exact reduction: chi^2 depends on the data only through `S = sum_p PB_p sig_p` and `Q = sum_p PB_p^2 W_p`; every derivative in position and shape is the model times a polynomial in (u, v), so one pass (`kernel.point_moments`, per-channel moments) gives chi^2, gradient and Gauss-Newton matrix exactly. The spectrum is fitted on the moments without another pass (trust-exact), and `scipy.optimize.minimize` (L-BFGS-B) moves position and shape, as two axis variances bounded at zero and an angle, on the profiled chi^2 from the matched filter's peak (4-16 passes a line); an axis on its bound gets a NaN error. `meta["spectra"]` keeps each line's spectrum and best fit; `imaging.line_maps` gives moment-0 maps. Errors `2 (J^T W J)^-1`, corrected for the channel correlation by a sandwich estimator (`_correlation_scale`). A failing line only warns. `luv-find --catalogue X --fit` writes the `fit_*` columns into the ECSV.
- `luv_finder/mock.py` — `MockObservation`: cube -> `simobserve` -> `tclean` -> `output/ms_files/<name>/`. YAML presets in `configs/mocks/`.
- `luv_finder/_casa.py` — the only place that imports `casatools`/`casatasks`. It presets `casaconfig.config.logfile` so CASA writes to `logs/` (override with `LUV_CASA_LOG_DIR`) instead of scattering `casa-<timestamp>.log` in the working directory. Never import CASA directly; use `tools()`/`tasks()`, or call `configure_logging()` first if you must.
- `luv_finder/utils.py` — constants `C`/`ARCSEC` and the analytic ALMA primary beam: an Airy pattern scaled to FWHM = 1.13 lambda/D (Technical Handbook, the real beam); simobserve's CASA beam is ~1.165, hence `tests/test_primary_beam.py` compares mocks with the default beam at 6%. Also the mock weight helper.
- `luv_finder/plotting.py` — all diagnostic figures; each takes a directory and returns the path written. `MatchedFilter.plot_response` is a thin wrapper.
- `luv_finder/cli/` — argparse wrappers only; no science logic.
- `configs/mocks/` and `configs/grids/` pair by filename; the `size_*` mocks take their source from the grid (`--grid`); `configs/README.md` covers the pairing. Antenna configs are not vendored: presets name files CASA ships (`alma.cycle13.3.cfg`), resolved by `mock.resolve_antenna_config`. `data/ output/ support/ plots/ logs/` are gitignored products.
- Test configs live in `configs/`, not under `tests/`: `tests/test_mock.py` loads `configs/mocks/smoke.yaml` and `configs/grids/smoke.yaml` rather than hardcoding parameters, so presets and tests cannot drift apart.

## Conventions

- DRY and KISS: one implementation per concept, thin wrappers, no speculative abstractions.
- Data I/O, the model and the mocks are numpy/scipy; the collapse (`kernel.py`), the filter, the imaging and the fit's derivatives are JAX. `model.envelope(..., xp=)` and `utils.primary_beam(..., xp=)` are the one formula each for both.
- No nested sampling or other samplers until ROADMAP.md says otherwise: detection is a grid search, and catalogued lines are refined by a deterministic least-squares fit (`fit.py`).
- No notebooks outside `docs/source/tutorials/`. New workflows become CLI commands + tests.
- Real-data organisation/concatenation belongs to `alma-data-prep`, not here.
- Planned work and open problems (JAX, catalog, primary beam + mosaics): see ROADMAP.md.
- Notion write-ups of the method (the Luv-finder page) read like a JOSS paper but are not for submission: explanation, math and code excerpts interleaved. Use the terminology of Vio & Andreani (2021, arXiv:2107.09378): H0/H1, template s, statistic T(x), SNR, P_FA, threshold gamma. Concise and accurate; state each thing once.
